# 多声部排练谱 · 小节对齐核对台

离线纯前端工具：用**整数分数（bigint 有理数）**累加各声部事件位置，核对标称小节号、拆分跨小节片段，并检查多个声部是否结束于同一完整小节线。全程不经过浮点，附点与三连音不会在小节线附近产生漂移。

## 运行（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:5173
```

容器外直接运行：

```bash
npm install
npm run dev        # 开发服务器
npm test           # Vitest 一次性测试
npm run test:watch
npm run build      # 类型检查 + 生产构建
```

## 输入

- 拍号：分子 2–12，分母 4 或 8（4 = 四分音符为一拍，8 = 八分音符为一拍）。
- 1–4 个声部，每声部 1–120 个**顺序**事件。
- 每个事件：
  - `id`：同一声部内唯一；
  - `bar`：标称小节号（1 起）；
  - `denom`：时值分母 `1 / 2 / 4 / 8 / 16 / 32`（全、二分、四分、八分、十六分、三十二分）；
  - `dotted`：附点，时值乘 **3/2**；
  - `triplet`：三连音，时值乘 **2/3**（可与附点同时勾选）。

## 算法

1. 事件时值 = `(1/denom) × (3/2 if dotted) × (2/3 if triplet)`，以全音符分数表示并约分。
2. 每声部从 0 开始用分数累加，得到每个事件的精确起点/终点。
3. 实际起始小节 = `floor(起点 / 小节长) + 1`；恰落在小节线上的起点归属下一小节，
   恰在线上结束的事件不会多出空片段（端点按半开区间 `[起点, 终点)` 处理）。
4. 标称小节号 ≠ 实际起始小节即错误；多个错误按**起始位置最早**报告（并列时取声部序号、再取事件序号）。
5. 跨小节事件按小节边界拆成显示片段，**片段保留原事件 id**；片段时长之和恒等于事件时值。
6. 共同目标终点 = 最长声部结束位置之后的第一条完整小节线；
   每个声部给出到该目标的**精确差额**（有理数），并标出未补足的声部。

最小公共刻度为 **1/192 全音符**（覆盖附点 32 分音符 3/64 与 32 分三连音 1/48，以及 12/8 小节 3/4），
时间轴上的所有位置都是该刻度的整数倍。

## 输出

- **并列时间轴**：各声部共享同一小节网格；色块为拆分后的片段（斜纹表示片段时长为非整数全音符），
  斜纹红区为未补足差额，第一个错误事件描红。
- **核对结论**：首个错误卡片、结尾对齐卡片、每个声部的事件表（实际/标称小节、起点、片段数）
  与显示片段表。
- **下载 JSON**：导出当前这一份核对结果（分数序列化为 `{__frac__:{n,d}}`，bigint 序列化为
  `{__bigint__:"..."}`），可按有理数离线复算。**输入一旦被编辑，旧结论立即标记失效且禁止下载，
  必须重新核对。**
